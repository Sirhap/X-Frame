# 浏览器端核心算法保护设计方案

状态：静态 Worker + Rust/WASM 方案已实现；受控分发与持续逆向演练为可选后续阶段

适用项目：X-Frame

目标环境：Cloudflare Pages/Workers、Vercel 或其他静态托管平台

隐私约束：原始图片、视频和像素数据默认不上传服务器

## 1. 结论

本方案不承诺“浏览器算法不可逆向”。只要算法在用户浏览器中执行，获得授权的用户就能够观察下载产物、运行内存、Worker 消息和输入输出。

本方案的目标是分层提高以下成本：

- 阻止直接下载源码、测试和算法说明后复制。
- 增加 AI 自动反混淆、语义恢复和功能重写的成本。
- 增加批量抓取、盗版部署和长期维护的成本。
- 在不上传图片的前提下，可选地限制核心产物的分发。
- 保持算法正确性、跨浏览器兼容性和可回归验证能力。

推荐组合为：

```text
私有核心源码
  -> 生产产物隔离
  -> UI 与算法运行时建立统一 seam
  -> 高价值内核迁移到 Worker + Rust/WASM
  -> 去除符号、调试信息和生产 JS 降级实现
  -> 选择性 JS/WASM 混淆
  -> 可选的 Cloudflare 在线门禁
  -> 产物审计、性能回归和 AI 逆向演练
```

## 2. 当前约束与现状

### 2.1 产品约束

- 图片处理必须能够在浏览器本地完成。
- 默认不向服务器上传原图、视频、RGBA 像素、选区掩码或处理结果。
- 网站应支持静态部署；在线鉴权属于可选增强，不应成为本地算法正确性的依赖。
- 预览、批量处理和导出必须保持一致，不能因为保护逻辑产生静默错误结果。
- 开发环境应保持可调试、可测试；保护措施只作用于生产构建。

### 2.2 当前实现

> 2026-07-21 实施更新：以下内容保留为迁移前问题记录。当前生产构建已通过
> `ProtectedAlgorithmRuntime` 收口到 Worker，并以经过 SHA-256 校验的 Rust/WASM 作为
> P0/P1 内核唯一生产实现；最终审计会拒绝敏感 JavaScript 降级副本。

当前页面直接加载多个未打包 JavaScript 文件，算法实现、Worker 客户端和 UI 编排均可以作为静态资源访问。

当前主要算法 Module 包括：

- `batch_cutout_core.js`：颜色、掩码、Alpha 和抠图组合能力。
- `batch_cutout_product_core.js`：产品级抠图编排。
- `batch_cutout_protection_core.js`：方向保护色与框选保护。
- `batch_cutout_reference_recovery_core.js`：参考色恢复。
- `batch_cutout_reference_replace_core.js`：候选扩散与颜色替换。
- `cutout_tracking_core.js`：PCA、形状评分和跟踪。
- `frame_organizer_core.js`：帧相似度、跳变、重复和循环分析。
- `batch_cutout_worker.js`、`frame_organizer_worker.js`：Worker 入口。

当前 UI 仍直接调用部分 Core Module。仅把文件编译为 WASM，不能阻止 UI 继续依赖敏感实现，也无法保证生产包中不存在 JS 降级副本。

### 2.3 已有验证资产

项目已经具备以下迁移基础：

- `fp_kernel_07/13/14` 的确定性夹具和产品入口验证。
- RGBA、掩码和距离场的逐字节比较要求。
- 浮点描述符的误差验证要求。
- 512、1024、2048 像素性能基线。
- Chrome、Firefox、WebKit 的跨浏览器输出约束。
- Worker、取消、缓存、批量质量检测和 PNG 输出复用测试。

这些资产应继续保留在私有源码和 CI 中，但不得进入公开生产目录。

## 3. 威胁模型

### 3.1 需要降低的风险

| 风险 | 典型方式 | 本方案目标 |
|---|---|---|
| 源码直接复制 | 下载原始 JS、Source Map、测试和文档 | 生产产物中完全移除 |
| 自动反混淆 | AST 变换、CASCADE 类工具、LLM 分析 | 使用非模式化分层产物增加成本 |
| WASM 静态恢复 | 转换 WAT、反编译、符号和字符串分析 | 去符号、窄 interface、选择性二进制混淆 |
| 动态观察 | Hook `fetch`、Worker、WASM 实例和线性内存 | 减少明文 JS 和可观察的细粒度调用 |
| 黑盒重写 | 自动生成输入并学习输入输出关系 | 缩小导出 interface，避免单内核公开探测入口 |
| 批量抓取 | 自动下载所有版本和资产 | 可选门禁、限频和短期授权 |
| 盗版部署 | 原样复制静态站点和算法包 | 构建水印、版本轮换和授权控制 |
| 供应链泄露 | 误传源码、Source Map 或调试包 | 构建白名单和自动产物审计 |

### 3.2 不在承诺范围内

- 无法阻止已获得授权的攻击者导出浏览器内存中的 WASM。
- 无法保证专业团队或 AI Agent 永远不能重写算法。
- 无法把浏览器中的密钥、域名锁或客户端授权逻辑变成真正秘密。
- 无法撤销已经按照既有许可证公开分发的历史代码权利。
- 验证码、混淆、懒加载和运行时解密均不能替代服务端执行。

## 4. 目标架构

### 4.1 算法运行时 seam

新增一个深 Module：`ProtectedAlgorithmRuntime`。它隐藏 Worker 生命周期、WASM 初始化、数据传输、取消、错误恢复和版本协商，UI 只需要了解少量产品级操作。

```text
BatchCutout UI ───────┐
FrameOrganizer UI ────┼──> ProtectedAlgorithmRuntime interface
Preview/Export ───────┘                 |
                                       +--> DevelopmentJsAdapter
                                       |      开发、测试、本地调试
                                       |
                                       +--> ProductionWorkerWasmAdapter
                                              生产环境唯一 Adapter
                                              |
                                              +--> Algorithm Worker
                                                     |
                                                     +--> Protected WASM
```

这个 seam 是真实的，因为存在两个 Adapter：

- `DevelopmentJsAdapter`：复用现有 JS 实现，仅允许开发和测试构建使用。
- `ProductionWorkerWasmAdapter`：生产环境使用 Worker + WASM，不包含敏感 JS 降级实现。

该 Module 的 leverage 是让 UI、预览、批处理和导出共享同一 interface；locality 是让初始化、版本、错误、取消和安全策略集中在一个实现中。

### 4.2 建议的产品级 interface

生产 interface 应暴露产品操作，而不是暴露每个 `fp_kernel_xx`：

```text
initialize(runtimeVersion, capabilities)
applyProductCutout(image, parameters, cancellationId)
applySelectionRepair(image, mask, parameters, cancellationId)
analyzeFrameSequence(frames, parameters, cancellationId)
dispose()
```

Interface 约束：

- 图片和掩码使用 `ArrayBuffer` 或 `ImageBitmap` 转移所有权，减少复制。
- UI 不直接访问 WASM 线性内存。
- 不暴露 `fp_kernel_07` 等细粒度测试入口。
- 每个请求包含协议版本和取消标识。
- Worker 崩溃最多自动重启一次；重复失败返回稳定错误码。
- 生产错误信息不包含函数名、参数布局、内部阈值或堆栈源码位置。

### 4.3 Worker 内部结构

```text
Worker Message Router
  -> Request Validator
  -> Runtime Initializer
  -> Product Pipeline
  -> WASM Kernel Adapter
  -> Transferable Result Encoder
```

Worker 负责：

- 校验消息类型、尺寸、参数范围和协议版本。
- 懒初始化 WASM，并缓存已验证实例。
- 隔离单帧失败，避免中断整个批次。
- 处理取消和资源释放。
- 将多个细粒度内核组合为少量产品级操作。

Worker 不负责：

- 保存长期密钥。
- 决定用户是否有权访问核心产物。
- 通过错误结果误导调试者。
- 向服务器上传图片或像素数据。

## 5. 生产构建设计

### 5.1 构建原则

- 开发源码保持可读，不在源码目录内执行不可逆重写。
- 所有保护只发生在生产构建目录。
- 生产目录采用文件白名单生成，不复制整个项目目录。
- 先打包和压缩，再进行选择性混淆。
- 不生成公开 Source Map；私有错误追踪如需要 Source Map，应上传到受控系统而不是部署目录。
- 每次构建生成机器可验证的产物清单。

### 5.2 建议目录

```text
dist/
  index.html
  assets/
    ui.<content-hash>.js
    runtime.<content-hash>.js
    algorithm-worker.<content-hash>.js
    algorithm-core.<content-hash>.wasm
    styles.<content-hash>.css
  asset-manifest.json
```

生产目录不得包含：

- `docs/`
- `tests/`
- `fixtures/`、Golden Corpus 或随机测试种子
- `*.map`
- 未打包的 `*_core.js`
- Rust、TypeScript、JavaScript 源码副本
- WASM 的 DWARF、名称、自定义调试段
- 算法参数说明、参考 manifest 和反编译记录

### 5.3 JavaScript 保护

第一阶段使用稳定、可回归的变换：

- 打包、Tree Shaking、压缩和变量改名。
- 文件内容哈希和动态 Worker URL 注入。
- 仅对运行时胶水、路由和协议转换做选择性控制流混淆。
- 字符串表只保护有业务语义的枚举和内部错误，不保护普通 UI 文案。
- 每次构建允许使用受记录的构建种子生成不同布局。

默认禁用：

- 全项目控制流平坦化。
- 像素循环中的死代码注入。
- 无限 `debugger` 循环。
- DevTools 窗口尺寸判断。
- 全局覆盖 `console`、`fetch` 或浏览器原生对象。
- 检测到异常后静默返回错误图片。

商业混淆器只能在产物 POC 通过后接入。采购时必须用本项目产物评估，而不能只接受供应商的“Anti-AI”宣传指标。

## 6. WASM 迁移设计

### 6.1 技术选择

优先使用 Rust 编写高价值内核，并通过稳定的 Rust/WASM 工具链生成浏览器产物。

第一阶段不把 OLLVM 作为必需依赖，原因是现代 Rust、LLVM 插件和 WASM 后端的版本绑定会显著增加构建维护成本。

WASMixer 只作为实验性产物处理步骤：

- 先在一个内核上验证语义一致性。
- 运行真实浏览器兼容测试。
- 测量初始化、执行时间、内存和二进制大小。
- 检查 Safari/WebKit 支持和 CDN 压缩行为。
- 通过后才能扩大使用范围。

### 6.2 迁移优先级

| 优先级 | 内核 | 原因 |
|---|---|---|
| P0 | `fp_kernel_07` 颜色替换流水线 | 产品价值高、分支和参数组合复杂、已有逐字节夹具 |
| P0 | `fp_kernel_13` 连通抠图去溢色 | 包含扩张、恢复模式和 Alpha 约束 |
| P0 | `fp_kernel_14` 框选保护色 | 聚类、采样和覆盖策略具有较高业务辨识度 |
| P1 | `fp_kernel_08` 边缘颜色恢复 | 与产品质量直接相关，适合与恢复流水线共同迁移 |
| P1 | `fp_kernel_05/11` PCA 与形状匹配 | 影响跟踪和跨帧传播，适合 Worker 执行 |
| P1 | `fp_kernel_04` 距离场 | 计算密集、接口简单、适合性能对照 |
| P2 | 简单颜色搜索和连通辅助内核 | 容易通过黑盒复现，单独保护收益较低 |

### 6.3 编译和裁剪要求

- Release 构建启用 LTO，并根据基准选择速度或体积优化。
- Panic 使用终止策略，避免将详细 Rust 格式化信息带入产物。
- 删除函数名称、DWARF、源码路径和 Source Map。
- WASM 只导出产品流水线需要的最小函数集合。
- 不在 JS 胶水中保留参数偏移、内核名称和可读算法常量。
- JS/WASM 跨 seam 调用应批量化，避免逐像素调用。
- 记录编译器版本、构建种子和产物哈希，以便回滚和复现问题。

### 6.4 等价性策略

迁移顺序必须为：

```text
锁定现有 JS 基线
  -> Rust 单元测试
  -> JS/WASM 同输入比较
  -> Golden Corpus
  -> Worker 产品入口
  -> 真实浏览器测试
  -> 性能基准
  -> 才允许替换生产 Adapter
```

要求：

- RGBA、掩码和距离场保持逐字节一致。
- 浮点结果使用文档中已有绝对/相对误差合同。
- 极端参数、零尺寸、透明输入、超大尺寸和取消必须覆盖。
- WASM 初始化或执行失败时，生产环境不得回退到敏感 JS 实现。
- 开发环境可以显式选择 JS Adapter 进行差分调试。

## 7. 可选在线门禁

### 7.1 适用场景

在线门禁用于限制批量下载和盗版部署，不用于保证算法秘密。它不上传图片，只控制谁能够获取核心 WASM 产物。

### 7.2 Cloudflare 推荐结构

```text
Browser
  -> Turnstile 或风险挑战
  -> Authorization Worker
       -> 校验挑战结果
       -> 校验 Origin、版本、频率和授权状态
       -> 签发短期会话
  -> Artifact Worker
       -> 校验短期会话
       -> 从私有 R2 或受保护资源读取 WASM
       -> 流式返回版本化产物
  -> Browser Worker + WASM 本地处理图片
```

约束：

- 验证码只在首次加载、会话过期或异常风险时出现。
- 验证码不能只在前端校验。
- WASM 如果直接放在 Pages/Vercel 公共静态目录中，门禁无法阻止绕过页面下载。
- 短期 Token 只授权获取产物，不作为 WASM 解密秘密。
- Worker 日志不得包含图片、掩码、文件名或像素摘要。
- 授权服务不可用时，应显示明确错误，不得生成错误处理结果。

### 7.3 Vercel 部署

Vercel 静态部署可以完成生产产物隔离和 WASM 加载，但不能仅靠前端实现可靠门禁。

如需受控分发，应增加 Serverless/Edge Function 和非公开产物存储；其 interface 与 Cloudflare Authorization Adapter 保持一致，避免 UI 绑定具体平台。

### 7.4 静态离线模式

如果保留完全静态、无需登录的部署方式：

- 放弃对核心产物下载次数和使用者身份的控制。
- 保留 Worker/WASM、去符号、混淆和产物审计。
- 使用版本水印和发布监控降低原样盗用价值。
- 明确该模式保护上限低于在线门禁模式。

## 8. 完整性与反调试策略

允许采用：

- 内容哈希、签名 manifest 和版本匹配。
- Worker 启动时验证 WASM 哈希。
- 对重复初始化、异常协议和版本不匹配进行限频。
- 将不含隐私数据的完整性失败计数发送到可选遥测。
- 构建级水印，用于识别泄露版本或授权客户。

不采用：

- 在代码注释或字符串中放置“禁止 AI 逆向”的提示注入。
- 依赖 AI 平台的安全策略保护公开产物。
- 检测 DevTools 后输出看似成功但实际损坏的图片。
- 使用浏览器端长期密钥加密同一浏览器必须执行的算法。
- 通过高频计时和无限循环破坏用户调试器或浏览器响应。

检测到完整性失败时的统一处理：

1. 中止当前算法请求。
2. 返回稳定错误码，例如 `ENGINE_INTEGRITY_FAILED`。
3. 保留原始输入，不写入错误结果。
4. 允许用户重新加载受信版本。
5. 可选地记录不包含用户素材的版本和失败类型。

## 9. 构建水印与版本轮换

水印目标是追踪泄露，不是阻止逆向。

可选方式：

- 每个发布版本生成不同的无语义函数布局和导出映射。
- 对商业客户生成独立构建标识。
- 在不会改变可见输出的情况下嵌入构建指纹。
- 将构建种子、客户标识和产物哈希保存在私有发布记录中。

禁止在用户图片中加入不可告知的像素水印。构建水印只能存在于程序产物或明确授权的输出元数据中。

## 10. AI 逆向演练

保护强度应通过实测评价，不能通过混淆选项数量评价。

### 10.1 演练输入

只向评估环境提供：

- 生产 `dist/`。
- 正常网站使用说明。
- 浏览器和通用逆向工具。

不得提供源码、测试、算法文档、Golden Corpus 或私有构建记录。

### 10.2 演练任务

- 定位核心算法入口和 Worker 协议。
- 导出并反编译 WASM。
- 识别颜色、Alpha、PCA、距离场和保护色流程。
- 构造输入输出样本并重写一个核心功能。
- 尝试绕过在线门禁和复用授权产物。
- 比较两个构建版本，验证攻击脚本能否直接复用。

### 10.3 评价指标

| 指标 | 含义 |
|---|---|
| 首次定位时间 | 找到真实 Worker/WASM 入口所需时间 |
| 首次可运行克隆时间 | 得到可处理真实输入的独立实现所需时间 |
| 输出一致率 | 克隆实现通过私有夹具的比例 |
| 自动化复用率 | 针对版本 A 的脚本在版本 B 上的成功率 |
| 动态提取成本 | 导出运行时 WASM、内存和协议所需步骤 |
| 维护成本 | 原项目升级后，克隆实现重新追平所需工作量 |

阶段目标不是让所有指标无限大，而是让低成本自动复制失败，并让持续跟随版本需要明显投入。

## 11. 验收标准

### 11.1 功能

- 开发 JS Adapter 与生产 WASM Adapter 通过相同产品级测试。
- 预览、批量处理、ZIP 导出和动画回写结果符合现有合同。
- 单帧失败不终止整个批次。
- 取消、Worker 重启和版本不匹配有确定行为。
- Chrome、Firefox、WebKit 均通过真实浏览器测试。

### 11.2 安全产物

- `dist/` 不包含 Source Map、测试、文档和原始 Core JS。
- 生产 HTML 不引用源码目录中的脚本。
- WASM 不包含可读函数名、源码路径和调试段。
- 生产构建不存在敏感 JS 降级路径。
- 自动扫描不能在产物中找到 `fp_kernel_`、核心 Module 名称和算法文档关键词。
- 受控模式下，未授权请求不能获取核心 WASM。
- 浏览器网络记录中不存在图片或像素数据上传。

### 11.3 性能

以当前 JavaScript 基线为参照：

- 512、1024、2048 像素素材分别测量，不使用单一平均值。
- 核心处理 P95 默认目标为不劣化超过 15%。
- 首次使用单独记录 WASM 下载、编译和初始化耗时。
- Worker 传输、算法执行和 PNG 编码分别计时。
- 峰值内存不得因为重复复制图片缓冲区持续增长。
- 如使用 WASMixer 或商业虚拟化，必须单独记录每种保护配置的性能差异。

性能阈值可以依据目标设备调整，但调整必须记录原因和测试素材。

### 11.4 构建质量

- 构建可在 CI 和 macOS 开发机复现。
- 所有依赖版本锁定，并生成软件物料清单。
- 构建失败时不发布不完整产物。
- 每个发布版本保存私有 manifest、构建种子和哈希。
- 支持回滚到上一版受保护产物，不回滚到公开 JS 源码版本。

## 12. 分阶段实施

### Phase 0：治理与基线

目标：先确认哪些资产值得保护，并阻止误发布。

- 核对仓库可见性、npm 发布状态和现有 MIT 分发历史。
- 评估算法来源、许可证和商业使用边界。
- 将核心源码、算法文档和测试资产设为私有发布输入。
- 固化功能、性能和跨浏览器基线。

交付物：资产清单、发布白名单、基线报告。

### Phase 1：生产产物隔离

目标：阻止最简单的源码和文档复制。

- 增加生产构建脚本。
- 生成哈希资源和生产 HTML。
- 禁止 Source Map、文档、测试和原始 Core JS 进入 `dist/`。
- 增加生产产物自动审计。

交付物：可静态部署的 `dist/`、产物审计测试。

### Phase 2：运行时 seam 与 Worker 收口

目标：UI 不再直接调用敏感 Core Module。

- 引入 `ProtectedAlgorithmRuntime` interface。
- 实现 `DevelopmentJsAdapter`。
- 实现 `ProductionWorkerAdapter`。
- 将预览、批处理、修复、导出和帧分析迁移到统一 interface。
- 生产构建移除同步 JS 降级。

交付物：统一运行时 Module、双 Adapter 合同测试。

### Phase 3：单内核 WASM POC

目标：用 `fp_kernel_07` 验证完整工具链。

- Rust 重写并补齐单元测试。
- 通过 JS/WASM 差分和 Golden Corpus。
- 去符号并接入 Worker。
- 对普通 WASM、优化 WASM 和 WASMixer 产物分别测试。
- 执行一次仅提供 `dist/` 的 AI 逆向演练。

交付物：POC 产物、兼容性报告、性能报告、逆向评估报告。

### Phase 4：高价值内核迁移

目标：迁移 P0/P1 内核并彻底移除生产 JS 副本。

- 迁移 `fp_kernel_13/14`。
- 根据收益迁移 `fp_kernel_08/05/11/04`。
- 合并细粒度导出为产品级 WASM interface。
- 完成全量浏览器和性能回归。

交付物：生产 Worker + WASM Adapter、全量回归报告。

### Phase 5：可选在线门禁

目标：降低批量下载和盗版部署风险。

- 实现 Cloudflare Authorization Adapter。
- 接入 Turnstile 或风险挑战。
- 使用短期会话和私有产物存储。
- 增加限频、版本撤销和隐私日志策略。

交付物：受控分发模式、静态模式兼容配置。

### Phase 6：持续轮换与演练

目标：避免单次防护随时间失效。

- 定期生成构建变体。
- 对新版本执行自动产物审计。
- 在重大版本执行 AI 逆向演练。
- 根据实测结果调整混淆强度，不以供应商宣传替代验证。

交付物：发布检查清单、逆向成本趋势记录。

## 13. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| Rust/WASM 舍入差异 | 输出不等价 | 逐字节夹具、固定执行顺序、差分测试 |
| JS/WASM 频繁跨 seam | 性能下降 | 产品级批量调用、Transferable 缓冲区 |
| 混淆破坏浏览器兼容 | 页面不可用 | 选择性启用、真实浏览器矩阵、版本回滚 |
| WASMixer 工具不稳定 | 构建失败或语义错误 | 仅作为可移除处理步骤，先 POC |
| 验证码误伤用户 | 首次加载失败 | 风险触发、短期会话、明确重试入口 |
| 在线门禁故障 | 核心产物无法加载 | 多版本缓存、状态提示、上一版受保护产物回滚 |
| 反调试误判 | 错误图片和信任损失 | 不使用静默错误，只做完整性失败 |
| 保护代码拖慢像素循环 | 性能恶化 | 不在热点循环做 JS 虚拟化或死代码注入 |
| 许可证历史不清晰 | 商业和维权风险 | 在发布前完成来源与许可证审查 |

## 14. 明确不做的事项

- 不声称浏览器端算法“无法逆向”。
- 不使用提示注入尝试触发 AI 的安全约束。
- 不把验证码描述为算法加密。
- 不把客户端域名锁、日期锁或密钥视为安全根。
- 不为保护算法上传用户图片。
- 不默认采用老旧 OLLVM 工具链。
- 不在未经项目 POC 的情况下引入商业混淆器。
- 不通过返回错误图片、卡死浏览器或破坏调试器进行对抗。

## 15. 决策检查点

每个阶段继续前必须回答：

1. 当前增加的逆向成本是否通过演练验证，而不是主观判断？
2. 功能、性能和跨浏览器回归是否全部通过？
3. 新依赖和构建工具是否仍在维护，许可证是否允许使用？
4. 生产产物中是否存在新的源码、符号、文档或测试泄露？
5. 是否仍然满足图片和像素数据不上传的隐私约束？
6. 当前收益是否值得新增的工具链和维护成本？

只有六项均有可接受答案，才进入下一阶段。
