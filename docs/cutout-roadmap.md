# 批量抠图架构与路线图

本文记录 X-Frame 本地抠图能力的模块边界、当前覆盖范围和后续优先级。实现目标是保持算法独立、可测试，并允许未来在不改动界面层的情况下迁移到 Web Worker、WebAssembly 或原生工具。

## 当前模块边界

- `batch_cutout_core.js`：颜色空间、背景估计、连通域、Alpha、柔化、去污、边缘恢复和保护色等像素纯函数。
- `cutout_tracking_core.js`：Alpha 连通候选、PCA 描述、形状评分、运动预测、严格模式、坐标映射和局部颜色重采样。
- `batch_cutout.js`：文件队列、参数状态、画布交互、局部修正历史、批量传播、导出及动画组替换。
- `self_test.js`：算法边界和数据映射的无浏览器回归测试。

## 已具备

- 边缘连通与全图背景清除。
- 自动背景估计、手动多背景样本、OKLab/YCbCr 感知色键。
- Alpha 双阈值、预乘 Alpha 高斯柔化、边缘颜色恢复和多模式去污。
- 单色与框选区域保护色；框选路径使用 YCbCr 方向聚类、亮度代表点和覆盖状态，最多保留 32 个代表色。
- 矩形智能清除、整块清空、主体恢复、撤销、重做与批量传播。
- PCA 局部坐标映射、最多 8 个主体候选、最近 3 次位移预测、连续失败 8 帧后的严格匹配，以及半径 15 的局部颜色重采样。

## 下一阶段

### P0：交互完整性

1. 统一选择掩码数据模型，支持 `replace`、`add`、`subtract`、`intersect` 四种组合操作。
2. 增加魔棒工具，支持连续和全局两种模式，并复用现有颜色距离与扫描线连通域。
3. 增加套索工具，使用 even-odd 填充生成掩码，并拒绝小于 40 像素的误操作区域。
4. 为智能传播增加逐帧结果列表，显示成功、跳过、严格模式和匹配分数，允许人工只重做失败帧。

### P1：质量增强

1. 增加独立的黑边恢复工具，把“正确颜色到污染颜色”的投影反解与通用边缘恢复分开，默认强度 85。
2. 增加仅作用于 Alpha Sobel 边缘的柔化模式，避免普通模糊影响主体内部细节。
3. 增加处理前后统计：全透明、半透明、边缘像素数、保护命中数和耗时。

### P2：性能与可扩展性

1. 把批量像素处理迁移到 Web Worker，加入取消、进度和单帧失败隔离。
2. 为重复使用的背景距离、Alpha 掩码和形状描述建立参数签名缓存，避免预览和导出重复计算。
3. 使用真实 512、1024、2048 像素素材建立基准测试；只有 JavaScript 基线稳定后再评估 WASM/SIMD。
4. 将参数整理为可版本化预设，例如白底像素图、绿幕动画、黑边素材和保守保护模式。

## 验收原则

- 所有算法先作为无 DOM 纯函数实现并补充回归样例。
- UI 层只负责编排、状态和展示，不复制颜色、形状或跟踪公式。
- 单帧失败不能终止整批任务，失败结果必须可定位、可重试。
- 默认参数变更需要保留旧素材的人工对比样例，避免只依据合成测试判断质量。
