# 项目导入入口交互设计

## 背景

项目中心目前把所有项目卡片都链接到 `/workspace`。空项目因此直接打开动画调参工作台，但工作台没有源帧，用户不知道如何把视频转换成图片帧，也无法在进入调参前完成导入与整理。

## 目标

- 空项目打开后先进入“导入视频 / 图片序列”流程。
- 已有动画帧的项目继续直接进入调参工作台。
- 导入流程必须在项目上下文内运行，抽帧结果可以继续进入整理、抠图和调参。
- 本地服务端项目和浏览器临时项目使用同一套入口判断。
- 保留显式的工作台深链接，熟练用户仍可直接进入调参界面。

## 方案

项目客户端摘要新增 `animationGroupCount`。项目中心依据这个字段生成入口：

- `animationGroupCount === 0`：链接到 `/workspace/tools/organizer?project=<id>`，按钮显示“导入视频 / 图片序列”。
- `animationGroupCount > 0`：链接到 `/workspace?project=<id>`，按钮显示“打开项目”。
- 字段缺失时保持现有工作台链接，兼容旧数据和第三方调用方。

服务端从项目 manifest 计算动画组数量并附加到项目摘要；浏览器运行时从 IndexedDB 中的项目 config 计算同一字段。项目中心的最近项目摘要和卡片使用同一状态，避免摘要显示“0 个动画组”但按钮却进入调参台。

## 数据流

```text
项目注册表 / IndexedDB
        ↓
项目摘要 + animationGroupCount
        ↓
项目中心 renderProjects
        ├─ 0  → 项目内导入器 → 视频抽帧 / 图片序列 → 整理 / 抠图 / 调参
        └─ >0 → 动画调参工作台
```

## 边界与错误处理

- 只有明确为数值 `0` 的项目才强制走导入入口；缺失或非法统计值不改变已有深链接行为。
- 视频抽帧失败、格式不支持和空结果继续由现有导入器显示错误，不在项目中心重复实现媒体处理。
- 浏览器临时项目刷新后从 IndexedDB 恢复统计值；若存储不可用，仍可使用当前会话内存状态。
- 直接访问 `/workspace`、`/workspace/tools/organizer` 和带 `project` 查询参数的深链接保持不变。

## 验收与测试

- 单元测试验证：空项目卡片和最近项目链接到项目内导入器，已有项目链接到工作台，缺失统计值保持旧行为。
- 浏览器运行时测试验证：导入动画后浏览器项目摘要的动画组数量更新。
- 端到端流程验证：从项目中心打开空项目时导入器可见，项目工作台画布不作为第一步；已有素材项目仍能打开工作台。
- 运行项目测试、Cloudflare 检查和生产构建，确认静态部署仍能提供两类入口。
