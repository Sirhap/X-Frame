# 散图切片识别框编辑设计

## 目标

让用户在散图切片自动识别完成后，直接修正误识别的裁剪范围并删除无效切片。所有缩略图、动画分组、单片下载和精灵表导出都必须使用编辑后的识别框。

本次只编辑切片矩形，不提供画笔、橡皮擦或像素级图像修改，也不增加手工创建新切片的能力。

## 交互设计

### 工具模式

画布工具栏提供两个互斥模式：

- `编辑切片`：识别完成后的默认模式。点击框体可选中，拖动框体可移动，拖动四边或四角控制点可调整大小。
- `取背景色`：点击源图采样背景色，并提示用户重新识别。

加载图片但尚未完成识别时，默认使用取背景色模式；首次成功识别后自动切换为编辑切片模式。明确的模式按钮替代当前同一次点击只能取色的隐式行为。

### 选择与编辑

- 点击识别框或下方缩略图会选择同一个切片。
- 选中框使用高对比描边并显示四角和四边共八个控制点。
- 拖动框体内部移动矩形；拖动控制点调整相应边界。
- 拖动过程按源图像素坐标计算，并实时刷新画布；指针释放后刷新缩略图、分组和导出数据。
- 选中框的 `X`、`Y`、`W`、`H` 显示在精确编辑区。输入提交后应用相同的边界约束。
- `W` 和 `H` 最小为 1；整个矩形必须位于源图范围内。
- 框体的 `pixels` 字段在手工编辑后更新为当前矩形面积，用于界面元数据，避免继续显示识别前的前景像素数。

### 删除

- 保留现有“删除选中”按钮。
- 当焦点不在输入框、选择框或可编辑元素中时，`Delete` 和 `Backspace` 删除选中切片。
- 删除后选择同一索引处的下一张；若不存在则选择前一张；删除最后一张后进入空结果状态。
- 删除按钮和键盘删除共用一个操作函数，确保分组、选择、缓存和状态提示一致。

## 架构与模块边界

新增独立的 `scatter_slice_editor_core.js` 纯逻辑模块，负责：

- 规范化未受信任的矩形与源图尺寸；
- 对移动增量进行边界裁剪；
- 按八个控制点调整矩形并保证最小尺寸；
- 根据画布坐标命中框体或控制点；
- 删除指定切片并计算新的选中索引。

该模块不访问 DOM 或 Canvas，可通过 Node 测试直接验证。

`scatter_slice.js` 继续负责页面状态、事件绑定和渲染，并调用编辑核心模块。拖动会使用 Pointer Events 和 pointer capture，保证指针离开控制点后仍能正确结束操作。为避免大图拖动时反复重建所有缩略图，拖动期间只重绘主画布；指针释放后再重建分组、缩略图和缓存。

`scatter-slice.html` 增加模式切换和坐标输入；`scatter_slice.css` 增加工具栏、编辑区和控制点相关视觉状态。页面在 `scatter_slice.js` 之前加载编辑核心模块。

## 数据流

1. 识别器产生 `state.boxes`，页面建立动画行分组。
2. 用户选中框后，页面记录原始矩形、命中区域和指针起点。
3. 指针移动时，编辑核心返回约束后的新矩形；页面替换当前框属性并重绘主画布。
4. 指针释放时，页面清除该框的切片画布缓存，按全部框重新分组，并尽量保留原有动画组是否参与导出的选择状态。
5. 数字输入、拖拽和删除都经过同一组提交函数，之后统一刷新界面。
6. 单片下载和精灵表拼接继续读取 `state.boxes`，因此自然使用编辑后的坐标和尺寸。

## 分组与选择规则

框体位置或尺寸变化可能改变其所属动画行。每次编辑提交后重新调用现有 `groupBoxesByRows`。

重新分组前记录每个框是否来自已勾选导出组；重新分组后，只要新组内至少有一个原本属于已勾选组的框，该组就保持勾选。首次识别仍默认勾选所有组。这样既能响应框体跨行移动，又不会因为微调尺寸而无条件重置用户选择。

## 异常与边缘情况

- 没有源图片或没有识别框时，编辑模式和坐标输入禁用。
- 画布 CSS 缩放与源图像素尺寸不一致时，所有坐标先转换到源图坐标。
- 无效、空白、非有限数字输入恢复为当前有效值，并显示错误状态。
- 反向拖过对边时，控制点停在最小尺寸边界，不翻转矩形方向。
- 编辑到源图边缘时截断移动或缩放，不允许产生负坐标或越界尺寸。
- 重新点击“开始识别”会替换全部手工编辑结果，这是显式重新识别行为。
- 输入框聚焦时不响应删除快捷键，避免删除数值时误删切片。
- Pointer 取消事件按当前有效矩形提交并清理拖动状态，避免界面卡在编辑中。

## 可访问性

- 模式按钮使用 `aria-pressed` 表达当前状态。
- 坐标字段带可见标签，并在无选中框时禁用。
- 画布的 `aria-label` 随模式变化，说明当前点击和拖动行为。
- 缩略图原有键盘选择能力保持不变。
- 删除快捷键只是增强能力，所有操作仍可通过按钮和输入字段完成。

## 测试策略

### 单元测试

为编辑核心模块覆盖：

- 移动矩形并限制在四条源图边界内；
- 八个控制点的缩放结果；
- 最小 `1 × 1` 尺寸；
- 画布 CSS 坐标到源图坐标的转换和命中优先级；
- 无效输入的拒绝或规范化；
- 删除首项、中间项、末项和唯一项后的选择索引。

### 页面结构测试

验证 HTML 加载编辑核心脚本，并包含两个工具模式、四个坐标字段和现有删除按钮。

### 回归测试

运行散图切片核心、分组、智能抠图和页面静态资源测试，确保识别、智能抠图和导出流程未退化。最后在真实浏览器中加载内置示例，验证选中、移动、八向缩放、数字编辑、按钮删除、键盘删除、重新分组和导出按钮状态。

## 完成标准

- 自动识别后可在画布直接选择、移动和八向缩放任一识别框。
- 可通过 X/Y/W/H 输入精确修改选中框。
- 可通过按钮或安全的键盘快捷键删除识别框。
- 编辑与删除后，主预览、缩略图、分组、计数和导出均立即一致。
- 所有矩形始终有效且位于源图范围内。
- 新增测试及相关既有测试全部通过，浏览器手工验证无控制台错误。
