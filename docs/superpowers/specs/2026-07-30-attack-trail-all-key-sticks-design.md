# 攻击拖尾全部关键棍显示设计

## 目标

攻击拖尾编辑模式同时显示当前拖尾段的全部关键棍，让用户可以直接看出开始、结束及中间关键姿态之间的关系，避免因画布只显示当前帧棍子而误判数据缺失。

## 交互设计

- 当前选中帧上的棍子保持现有实色、描边、发光、编号和拖拽交互。
- 其他帧上的棍子以较低透明度显示，仅作为不可交互的姿态参考。
- 橙色继续表示棍子位于角色前层，蓝色继续表示棍子位于角色后层。
- 非当前帧棍子的编号继续使用全局顺序，例如 `#1`、`#2`、`#3`，便于识别运动方向。
- 选中路径辅助线仍围绕当前棍子及相邻关键棍生成，不改变现有曲线编辑方式。

## 实现边界

- 只修改 Web 编辑器的关键棍辅助线绘制逻辑。
- 不修改 `attack_trails.json` 数据结构。
- 不修改拖尾插值、网格生成、导出采样或 Godot 运行时。
- 不新增设置项或工具栏按钮；开启现有“棍”辅助线后即显示全部关键棍。

## 绘制与交互规则

1. 绘制阶段遍历当前拖尾段的全部 `sticks`，而不是只遍历当前帧的 `sticks`。
2. 当前帧棍子沿用现有透明度：选中为 `1`，未选中为 `0.82`。
3. 非当前帧棍子使用固定的低透明度，并且不显示选中发光，避免与当前编辑对象竞争视觉焦点。
4. 指针命中检测仍只遍历当前帧棍子，保证用户不会在当前角色帧上误改其他关键帧数据。
5. 帧切换后，新的当前帧棍子自动恢复为可交互实色，之前帧的棍子退回半透明参考状态。

## 边缘情况

- 当前拖尾段没有棍子时不绘制任何辅助线。
- 只有一根棍子时正常显示，但仍提示至少需要两根才能生成拖尾。
- 同一帧有多根棍子时，它们全部保持当前帧样式并可按现有规则选中。
- 被禁用或尚未生成拖尾的段仍可显示已放置棍子，延续现有编辑体验。
- 隐藏“棍”辅助线或退出拖尾模式时，不绘制任何关键棍。

## 测试策略

- 增加回归测试，证明绘制辅助线使用全部关键棍，而指针交互仍限制在当前帧棍子。
- 验证非当前帧棍子使用参考透明度，且不触发选中发光。
- 运行拖尾 UI、拖尾数据规范化、Godot 交接和相关完整测试。
- 运行 JavaScript 语法检查与项目 ESLint，确认修改符合现有规范。

## 验收标准

- 开始帧放置一根棍子、结束帧放置另一根后，无论停在哪个关键帧，都能同时看到两根棍子。
- 当前帧棍子明显突出，其他帧棍子清晰可辨但不喧宾夺主。
- 橙/蓝颜色仍准确反映角色前后层。
- 非当前帧棍子无法被当前帧的鼠标操作意外拖动。
- 拖尾预览、导出和 Godot 运行时结果与修改前一致。
